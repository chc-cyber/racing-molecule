# 分子赛车工坊

二维使用本地 **Ketcher 3.18.0 + C₆₀ 扩展 .3（模板数据 v2）**，三维使用本地 **JSmol 16.3.31 ModelKit + Ketcher 风格侧栏与原生编辑手势**。两套工具共用真实分子拓扑、稳定原子 ID 和撤销记录。运行不需要 CDN、Java、账号或 npm 安装。

## 打开

按项目原有方式启动后打开 `http://127.0.0.1:8765/editor/index.html`。本轮增加候选赛车准备接口，旧 Python 服务需重新启动才会加载新模块；已有服务需要保留时，可另开下方独立实例。

独立工坊实例：

```powershell
.\.venv\Scripts\python.exe -E -B -m molecular_car.server --port 8786
```

打开 **http://127.0.0.1:8786/editor/index.html**。初次加载本地成熟组件体积较大。开发测试只使用独立实例，不能停止其他人正在使用的服务。

## 界面文案

图标提示使用动作名称和快捷键；底栏显示模式、选择状态和原子/键数量。正常反馈只报告操作结果，异常反馈说明问题和处理办法。几何接口以 `message` 返回完成结果，`warnings` 返回需要关注的结构、立体或计算事项，界面优先显示这些事项。构象、编号、临时计算副本等开发说明留在本文档。旧工程的 C60 操作说明兼容过滤；实际手性和价态提示继续显示。

原生 C60 放置指引通过 Ketcher 的消息订阅显示在工坊状态栏；角度调试信息等其它原生消息不转接。

## 操作

1. **二维绘图**：使用 Ketcher 原生选择、原子、键、环模板、电荷和立体键工具。右侧周期表可添加或替换元素。底部原生环模板包含 C₆₀，旧赛车片段库和旧自定义片段入口已移除。
2. **进入三维**：自动构建合理的初始位置并补入真实氢，**不自动执行 UFF 整理，也不要求 UFF 参数支持**。后续新增结构只构建新增部分；原有原子，包括新连接的旧锚点，保持其构象。只调整二维排版或普通视图往返不会优化旧构象。
3. **三维原生操作**：左侧提供选择、Atom 原子工具、化学键、删除、移动原子、移动基团、绕键旋转及测量。原子工具直接显示 Atom 四个字母；右侧元素符号加粗，当前元素由高亮与状态文字表示。化学键是一个工具：点击已有键改为当前单/双/三键；从原子拖到原子连接，拖到空白延伸当前元素，单击原子只确定起点。连接检查价态，保留手动/导入 H；必要的自动 H 替代和 C60 加成降级与连接一起撤销。三维右键菜单与左上原生菜单入口关闭，操作统一从侧栏、周期表和选中后的按钮进入，原生编辑手势继续有效。二维 C60 的右键展开仍保留。绕键旋转使用化学键穿过单箭头椭圆环的图标，箭头头尾留有缺口；空白拖动转相机，滚轮缩放，移动分子时 Alt 拖动旋转。
4. **精确几何**：通过几何面板按顺序选择 2 / 3 / 4 个连续原子，输入键长、键角、二面角。预览后点应用或取消；环内键不能分离时会提示。属性面板可输入所选部分的平移、旋转。键盘 V / M / R / G 等快捷方式仍可用。
5. **保存和撤销**：工坊所有操作使用同一份历史。顶部保存项目下载 `.mcar`，导出按钮可导出 2D / 3D MOL 或单分子 SDF。点击“保存并进入赛道”下载工程并自动检查和准备赛车，成功后在同一页进入赛道。

二维左栏的 R 基团、反应编辑和图形注释整组通过 Ketcher 原生 `hiddenControls` 配置移除，相关快捷入口仍受控。选择与键型下拉、元素、电荷、基础环模板及 C60 折叠/展开保留。常驻橙色提示条已移除，C60 加成仅在白色状态栏提示一次；未解决的价态/手性问题显示为可点击的警告计数，详情保留具体原因。旧工程里误存为结构警告的 C60 操作说明不再重复显示。

## C₆₀

C₆₀ 默认使用 **Ketcher 原生 SUP Superatom 化学式缩写**，内部始终保留 60 个真实碳原子、90 条键。右键缩写可展开、收缩；展开时是完整的平面化学图。三维使用已知球壳坐标，不把二维展开图当成三维构象。

先在空白处放置，再用原生单键连接。模板不能融合到已有原子或键，避免把原有氢或碳替换成过价笼碳。单键连接采用明确的加成处理：将连接位点相邻的笼内双键降为单键，显示说明，与外接键一起撤销。其它连接端满价时拒接；手动或导入的显式氢须先明确处理。

原生“移动原子 / C60 组”拖动笼时，按明确组成员移动整个笼及直接连接的末端氢，车身其余原子保持。双击选择整个相连分子。导入的折叠 SUP 也可按文件声明的成员整体移动。

## 构象、身份与三维准备

`model.js` 保存唯一拓扑及独立 `pos2`、`pos3`。二维排版不覆盖三维；移动不按距离推断、增加或删除化学键。Ketcher Pool、JSmol MOL 行和整数 `property_editorid` 都通过明确映射关联 UUID，不靠 SMILES 或图匹配恢复对称分子身份。交错排列的未连接片段在 KET 传输前按已知连通部分排列，并同步显式引用表，避免 Indigo 导入重排导致编号错绑；玩家保存的 ID 和坐标不改变。

`metadata.ketcherGroups` 保存原生 SUP 的成员、缩写、展开状态及连接点。原生 C60 模板携带有序来源映射，其真实球壳初始 C–C 键长为 1.42 Å。普通文件中的 SUP 成员按文件编号映射读取，不猜测模板来源。

化学编辑记录 `metadata.geometryPending`。`prepare` 为新增原子生成合理三维初始位置，再补氢，不执行 UFF。已有构象中的旧原子坐标精确保留，改动旧元素、电荷或键级也不会自动重新安排旧坐标；需要时显式整理。手性标签因邻接变化而失效会提示，不借此自动移动旧锚点或翻转手性。

原生三维创建、移动及精确几何应用会在同一次撤销交易中确认实际摆放的原子，移除对应待构建标记。随后二维往返只补缺失氢，不覆盖这些手工坐标；没有被移动的其它新增部分继续等待构建。

C60 使用已经保存的真实球壳种子。甲基等新增结构沿连接位点向外放置，较复杂的新片段单独生成并对齐，避免让整颗旧球壳参与构象生成。普通首次结构使用 ETKDG 初始构象；构象生成和补氢不代表能量已经最小。

自动补入的 H 标记 `generatedHydrogen:true`。明确新增连接占用价态时，只替代必要的自动氢，与成键一起撤销。玩家绘制或从 MOL 导入的 H 不被自动删除。标记保存在原生项目中；普通 MOL 不保存氢的编辑来源。

拖动不运行优化。异步结果同时核对修订、交互版本和请求序号；旧结果不能覆盖新设计。原生移动更新精确增量后保留 live 模型，不每次拖动重载。程序加载和用户事件隔离，避免循环同步。

接入层还过滤 JSmol 进入画布时没有按下动作的假点击：鼠标重新经过上次点击的原子不会擅自改变选择或分子。正常选择、多选和拖动仍由原生手势执行，选中一个原子后可在周期表直接替换并撤销。

## 显式整理与文件

- **重新生成三维（立方体）**：只重建三维坐标，保留拓扑、原子/键 ID 与二维排版；不补入显式氢、不执行 UFF，可撤销。C60 继续使用明确映射的球壳。内部生成副本可带临时 H，不写入工程。
- **补氢（+H）**：仅添加缺少的真实氢及连接键，两视图均可用；保留原有两套坐标与 ID，不切换视图、不优化，可撤销。
- **UFF 优化（能量下降曲线）**：仅在 3D 显示，从当前构象优化，可固定所选原子；临时副本里的 H 不写入工程，不重建整体构象，可撤销。
- **整理二维（平面环与对齐标记）**：仅在 2D 显示，只整理二维排版及一致的楔线表示，保留三维构象，可撤销。返回二维时在画布可见后完整重绘，防止氢文字与键端点分离。

正常 2D/3D 切换仍调用 `prepare`，只构建新增区域并自动补氢，不重建旧构象或执行 UFF。独立几何接口新增 `rebuild`；旧 `generate` 的组合语义仅留作兼容与历史测试，当前页面和原生菜单都不再调用它。适配视图与右下角视角复位统一使用四角框。+H 中的 H 使用普通字体的粗体字形；UFF 能量曲线图标的箭头缩小并与曲线留出间距。

固定旧端点的新连接可能保留不合理键长。准备服务只对本轮相关固定连接提示；玩家可移动片段或显式整理。复杂多点连接不兼容时会明确说明，原有设计保持。几何或化学准备失败后，有三维的未完成设计仍可打开、修改和保存，并明确显示未完成原因。

`.mcar` 精确保存 UUID、两套坐标、立体信息、SUP 和准备状态。MOL / 单分子 SDF 保存真实完整结构；SUP 使用 V3000，保留名称、成员、连接点和展开状态。MOL 重新导入会获得新工程 UUID，但三维文件保持输入构象；不自动补氢或优化。V2000 四位小数、V3000 六位小数带来坐标舍入。多记录 SDF 明确拒绝，未提供记录选择器。

支持四面体手性、楔线/虚楔和双键 E/Z。AND/OR 增强立体组、非四面体立体化学、查询、反应、聚合物和非 SUP S-groups 尚不支持。未应用的几何预览需先应用或取消才能保存、导出和试跑。

三维常驻键图标使用原生单、双、三键，拖动连接使用所选键级；芳香键和楔线在 Ketcher 或属性面板编辑。只有原生模板及原生工程保存明确的 C60 种子来源；不按普通文件的缩写名称猜测模板身份。纯二维笼结构文件需要普通构象生成，可能无法生成；保存设计优先使用原生工程或三维 MOL/SDF。

整理二维排版先在私有副本上识别原子的杂化状态，使普通炔链的三键两端按 180° 排成直线，同时重新布置一致的立体楔线。稳定 ID、键级、三维构象及片段记录保留；该操作可撤销，也允许未完成的结构。环内三键仍由绘图工具的环约束处理，不能保证任意小环中的键角都变为 180°。

## 赛道与限制

完整的保存、检查、候选准备、成功后进入赛道及上一场轨迹说明见 [完成流程](COMPLETION.md)。主按钮统一为“保存并进入赛道”，普通“保存工程”继续独立提供。

可编辑保存与可试跑分别判断。当前引擎要求单连通图、闭壳层、补氢后不超过 256 原子、常规键及完整 UFF/Gasteiger 参数等，并检查联合几何松弛。只在玩家点击“保存并进入赛道”时创建候选准备任务；工坊不调用 `/api/load`。候选任务通过完整准备后才提交切换，失败或取消不修改当前比赛。

主模拟任务同步改善了准备阶段的收敛策略，保持原受力阈值。最终联合验收中，苯分子及恢复原生工程精确坐标后显式整理的 C60–苯加成样例都成功通过真实 LAMMPS 加载。此前一次文件往返构象的 C60 试跑被联合松弛残余力阈值拒绝，页面正确显示原因。保存设计应使用原生工程；几何整理收敛不等于保证所有构象都能通过赛道准备。

赛道仍补氢、松弛并平移，比赛构象可能不同。本轮未改力场、表面、驱动、加载语义或赛车表现层。C60 复杂多点外接的自动准备尚未完整验收；没有多构象管理、增强立体组、完整剪贴板连续链或手机触摸专项优化。
