# JSmol 主三维宿主：实现与实际验收

验证日期：2026-10-13。主工坊的三维渲染、实时拖动和选中组旋转使用本地 JSmol 16.3.31。增删原子、元素/电荷修改、连键及键级修改实际执行 ModelKit 命令，再由适配层只接纳用户明确要求的改动。主工坊入口为 `/editor/index.html`；原生行为研究页 `/editor/research/jsmol-live.html` 保留用于复现上游副作用。

## 为什么保留一层宿主

实际运行发现，即使关闭补氢与自动成键，原生 ModelKit 的元素替换仍可能删除已有氢、移动邻接原子。直接回收工具内部整份结构会损坏玩家设计。因此 `jsmol-host.js` 记录一次鼠标操作的意图，`jsmol-adapter.js` 核对原生动作确实发生，再从共同项目副本只更改指定字段。

| 动作 | 接纳内容 | 保留内容 |
|---|---|---|
| 拖动 / 选中组旋转 | 被实际移动的选中原子的三维增量 | 其余精确坐标、全部二维坐标、化学图和立体字段 |
| 元素 / 电荷修改 | 目标原子的指定字段 | 已有氢、键和全部坐标 |
| 添加原子 / 连键 | 明确新原子以及明确端点间的一条键 | 工具可能产生的默认原子或附带化学调整均不采纳 |
| 改键 / 删键 | 目标键的键级或删除该键 | 其它键、原子和坐标 |
| 删除原子 | 目标原子及其关联键，修剪片段引用 | 其它原子，包括可能断开的显式氢 |

每次接纳后通过 `WorkshopModel.commit` 产生一个共同历史步骤。化学编辑重新加载规范项目，清除原生副作用；纯坐标手势保留原生模型和相机，只更新精确坐标的差分基线。模型的拓扑立体检查仍会执行；这里不推断手性，不把 JSmol 索引当作永久身份。未完成、价态不合理的结构仍可编辑和保存；试跑条件由另外的准备流程判断。

## 身份、载入与坐标

宿主在浏览器中构造独立 V3000 查看传输，不请求化学导出服务。传输的行顺序由 `indexToAtomId` 显式给定；JSmol 的 `property_editorid` 保存可精确表示的数字 token，外部字典对应项目 UUID。增删或 C60 的对称性都不会触发图匹配、SMILES 匹配或距离成键。

载入后按明确身份恢复输入三维坐标。工具浮点表示可能有微小误差，所以拖动只回收相对于鼠标按下时原生坐标的增量；没有移动的坐标保留原项目数值。`pos2` 与 `pos3` 始终独立。芳香键在 JSmol 中有时以 `aromaticSingle` / `aromaticDouble` 显示；适配器依据这些明确类型保存语义键级 1.5，不把它们误当成普通单/双键。

通用 `loadProject` 还处理了实测的上游 V2000 边界：带虚楔的三维单键可能被读成 `aromaticSingle`。载入后先核对键数和明确端点，仅恢复现有边的规范项目键级，然后再次检查一致性；缺失边或改变端点会拒绝，不会按距离补边。主宿主的查看传输不传二维楔线，但通用入口也需覆盖这个问题。原生研究页的 15 项回归包含手性 MOL 完整往返。

一次操作绑定项目修订号。父页面更新项目会取消未完成的原生手势，旧鼠标释放不能覆盖新设计。鼠标释放与延迟读取之间的撤销会先记录该次操作，再撤销该操作。原生菜单 undo / redo 已转接共同历史；独立 restore state 入口关闭。选择和几何模式显式设置 `identifyBond` 清除旧的键赋值模式，因为单独 `bondPicking false` 不能清除上游动作状态。

## 接入契约

```javascript
const host = new JSmolHost(container, {
  model,
  onSelection(ids, bondId) { /* 更新共同选择 */ },
  onInteraction() { /* 取消过时异步意图 */ },
  onError(error) { /* 展示具体原因 */ },
  onReady() {},
  onMode(mode, options) { /* 只更新操作说明，不再次设置原生模式 */ },
  onAction(name) { /* 共同几何、历史、保存和导出 */ },
});
await host.initialized;
model.addEventListener('change', () => {
  if (!host.isApplying) host.push(model.project);
});
await host.settled();
```

宿主不自行监听模型，避免重复载入。公开 `ready`、`suspended`、`gesture`、`isApplying`、`applet`、`adapter` 和 `viewer` 用于联动及验收。常用方法有 `push`、`flush`、`settled`、`setMode`、`setSelection`、`resetView`、`onVisible`、`showPreview`、`clearPreview`、`setNumbers`。模式为 select / move / molecule / rotateBond / rotate / atom / bond / delete / charge / measure。三维几何预览只读，应用由共同模型负责。原生菜单和最新回调约定见 [原生 ModelKit 接入](jsmol-native.md)。

双击一个原子会按共同项目的明确键关系选择整个连通分子；再用移动或旋转模式可整体操作 C60。多原子选择可由父页面传入。键选择使用现有键的屏幕投影线段，原子优先；这仅用于命中目标，不推断化学键。

首次初始化需要非零尺寸。当前使用数值启动尺寸并支持显示后的容器缩放；父页面保留隐藏三维容器的布局尺寸。

## 真实浏览器验收

在项目根目录运行：

```powershell
node frontend/editor/tests/jsmol-host.cjs
```

脚本使用自己的 Chrome 无头浏览器与静态文件请求拦截，不启动或停止服务器，不调用任何 `/api/`，不访问外网。它读取现有 RDKit 环境生成的测试项目。依赖路径与覆盖环境变量见 [原生 runtime 验证](jsmol-live.md)。

最近一次 **18 / 18 项通过**，记录为 `outputs/editor-jsmol-host-check/report.json`，截图为同目录 `host-chiral.png` 和 `last-state.png`。

1. 空白画布真实点击只添加一个 C，没有默认甲烷、氢或键。
2. 空白画布真实连键拖动产生两个原子、一条键、一个历史步骤。
3. 连键模式两个空白点击产生两个不同位置的原子及明确键，没有重合默认原子。
4. 芳香键修改经规范项目重载仍保持语义键级 1.5。
5. 真实原子拖动实时改变工具坐标；释放后只改变选中 `pos3`，精确未移动坐标、二维、键图和相机不变。
6. 统一撤销 / 重做恢复完整构象和稳定 ID。

10. 元素替换保留已有氢、所有键和坐标，过滤原生附带删除和键长调整。
11. 形式电荷只改变目标电荷。
12. 真实键点击改三键保留所有原子与坐标。
13. 删键只移除目标键。
14. 删原子只移除目标及关联键，保留其余显式氢。
15. C60 真实原子拖动仍为 60 原子 / 90 键，全部 ID 保留。
16. 双击 C60 选择明确连通的 60 原子，真实拖动使全部原子同向等距移动。
17. 手性项目的坐标预览只读，取消后规范项目及 ID 完整恢复。

主页面双编辑器、文件往返、服务和赛道联动由另一套主页面测试负责，见 [工坊验收记录](../VALIDATION.md)。本脚本不把独立宿主验收冒充整个产品验收。

## 已知边界

- 原生 ModelKit 菜单已启用，保存、撤销和几何菜单通过原生源码中的动作桥接使用共同工程。通用原生主菜单不再作为产品入口。
- 几何微调可能造成与原手性标记冲突；这里保留规范立体信息，导出 / 几何准备服务负责明确检查，不静默改构型。
- 有明确 SUP 成员记录的 C60 与其它折叠基团，普通点击拖动即可整体移动，直接连接的末端氢随行。没有基团元数据的普通原子可独立编辑；双击按明确键关系选择整个连通分子。
- JSmol 的 Java2Script 会覆盖全局 `Error`。自有模块需在异步 runtime 初始化前词法捕获浏览器原生 `Error`；主宿主和适配器已如此处理，并支持从运行时保存的 `Clazz._Error` 获取原构造器以兼容延迟模块导入。不要依赖初始化后的全局构造器保存错误消息，也不要随意替换回全局构造器而破坏上游惰性 Java 类。
- 工具全局调试对象仍可由开发者控制台直接调用；产品界面的所有编辑经过宿主。浏览器控制台不是受限制的安全边界。

固定版本、完整上游许可与文件哈希位于 [JSmol NOTICE](../vendor/jsmol/NOTICE.md) 及相邻 manifest。原生菜单源码扩展及上游原件位于 [jsmol-source](../jsmol-source/README.md)，没有重新打包分子渲染核心。
